# TrueFit — API Reference (v1)

> Built from **PRD.md** (features M1–M14, V1–V11 — numbers below match PRD §4) and **DATABASE.md** (tables). TrueFit has no custom app server: the API is **Supabase** — Auth (`/auth/v1`), PostgREST over the tables (`/rest/v1`), Postgres functions (`/rest/v1/rpc`) and Edge Functions (`/functions/v1`). The app calls these only through the wrappers in `src/lib/supabase.ts` and `src/sync/*` (see ARCHITECTURE.md). Most screens read **local SQLite**; the network is used for auth, sync push/pull, RPCs and functions.

## 0. Common rules

**Base URL:** `https://<project-ref>.supabase.co` (env `EXPO_PUBLIC_SUPABASE_URL`). Local: `http://127.0.0.1:54321`.

**Headers (every request):**
| Header | Value | Notes |
|---|---|---|
| `apikey` | `<EXPO_PUBLIC_SUPABASE_ANON_KEY>` | Public anon key; never the service role key |
| `Authorization` | `Bearer <access_token>` | Required for everything except sign-up/sign-in/OTP/recover |
| `Content-Type` | `application/json` | For bodies |
| `Prefer` | `return=representation` / `resolution=merge-duplicates` | PostgREST behaviour |
| `X-Client-Info` | `truefit-android/<version>` | Set by supabase-js; used in logs |
| `X-Request-Id` | UUID v4 | Generated by the client; echoed in errors |

**Roles:** `anon` (not signed in) · `owner` (= Postgres role `authenticated`, signed in, RLS limits to own shop) · `owner+plan` (owner whose plan is `trialing`/`active`/`grace`, checked by `shop_can_write()`) · `service` (service role, Edge Functions/webhooks only).

**Pagination:** `limit` + `offset` query params, or `Range: 0-49` header. Default page 50, max 500 (sync pull uses 500). Responses with `Prefer: count=exact` return `Content-Range: 0-49/312`.

**Filtering:** PostgREST operators — `col=eq.x`, `neq`, `gt`, `gte`, `lt`, `lte`, `in.(a,b)`, `is.null`, `ilike.*x*`, `or=(a.eq.1,b.eq.2)`. Always add `deleted_at=is.null` for live rows (sync pull is the exception: it needs tombstones).

**Sorting:** `order=due_date.asc,order_no.desc`. Sync pull always uses `order=updated_at.asc,id.asc`.

**Field selection:** `select=id,name,orders(id,order_no)` (embedded relations via FKs).

**Rate limits:**
| Area | Limit |
|---|---|
| Auth: sign-up / sign-in with password | 30 per 5 min per IP (Supabase default, configured in `config.toml`) |
| Auth: email OTP / magic link / recovery | 1 per 60 s per email; 30 emails/hour project-wide (custom SMTP raises it) |
| ~~Auth: phone OTP send~~ | Removed 2 Nov 2026 (no phone sign-in) |
| Auth: OTP verify | 30 per 5 min per IP |
| Auth: token refresh | 150 per 5 min per IP |
| REST + RPC | No Supabase-side per-user limit; client caps sync to 1 push + 1 pull per 5 s; DB statement timeout 8 s for `authenticated` |
| `ai-chat` (V2) | 30 requests/hour and 200/day per shop (counted in `ai_usage`) |
Exceeding a limit returns **429** with `RATE_LIMITED`.

**Standard error format** (Edge Functions return it directly; Auth/PostgREST errors are mapped to it by `src/lib/errors.ts` so the app only ever sees this shape):
```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Phone must be a 10-digit Indian mobile number.",
    "details": { "field": "phone" },
    "request_id": "6c1f6a0e-2b7e-4c31-9b0f-7f0f4c2c0a11"
  }
}
```
| HTTP | `code` | Source mapping |
|---|---|---|
| 400 | `VALIDATION_FAILED` | PostgREST `23514` (check), `22P02` (bad input), `PGRST102`; Auth `validation_failed`, `weak_password` |
| 401 | `UNAUTHENTICATED` | Missing/expired JWT, `PGRST301`, Auth `invalid_credentials`, `otp_expired` |
| 402 | `PLAN_REQUIRED` | RLS insert blocked by `shop_can_write()` (`42501` on customers/orders insert while plan expired) |
| 403 | `FORBIDDEN` | `42501` otherwise (RLS), service-only route |
| 404 | `NOT_FOUND` | `PGRST116` (no row for `.single()`), unknown function |
| 409 | `CONFLICT` | `23505` (unique: order_no, measurement per cloth, cloth name), `23503` (FK) |
| 422 | `BUSINESS_RULE` | Raised by RPCs (`P0001`), e.g. order without measurements |
| 429 | `RATE_LIMITED` | Auth `over_request_rate_limit`, `over_sms_send_rate_limit`, AI limit |
| 500 | `INTERNAL` | Anything else |
| 503 | `UPSTREAM_UNAVAILABLE` | Twilio/Anthropic/RevenueCat down |
| — | `NETWORK_OFFLINE` | Client-side only (no response) |

**Versioning:** Breaking changes ship as a new path prefix for Edge Functions (`/functions/v1/ai-chat` → `ai-chat-v2`) and, for tables, as additive-only migrations. If a table change must break, a new Postgres schema `api_v2` is exposed and clients send `Accept-Profile: api_v2` / `Content-Profile: api_v2`. The app sends its version in `X-Client-Info`; forced updates use Google Play in-app updates (no endpoint).

## 1. Auth (`/auth/v1`) — PRD M1

### 1.1 Sign up with email + password
`POST /auth/v1/signup` · **anon**
```json
// request
{ "email": "owner@shop.in", "password": "Strong#Pass1", "data": { "full_name": "Harsh Vaghela" } }
// 200
{ "user": { "id": "0b6…", "email": "owner@shop.in", "email_confirmed_at": null }, "session": null }
```
Confirmation email sent (6-digit code). Errors: 400 `VALIDATION_FAILED` (weak password: <8 chars or breached), 409 `CONFLICT` (`user_already_exists`), 429.

### 1.2 Verify email code
`POST /auth/v1/verify` · **anon**
```json
{ "type": "signup", "email": "owner@shop.in", "token": "482913" }   // email confirm
{ "type": "email",  "email": "owner@shop.in", "token": "482913" }   // email OTP / magic code sign-in
{ "type": "recovery", "email": "owner@shop.in", "token": "482913" } // reset password
// 200
{ "access_token": "eyJ…", "token_type": "bearer", "expires_in": 3600, "refresh_token": "v1.Mr…", "user": { "id": "0b6…" } }
```
Errors: 401 `UNAUTHENTICATED` (`otp_expired`, wrong code), 429.

### 1.3 Sign in with password
`POST /auth/v1/token?grant_type=password` · **anon** — `{ "email": "...", "password": "..." }` → 200 session (as 1.2). Errors: 400 `email_not_confirmed`, 401 `invalid_credentials`, 429.

### 1.4 Request OTP — not used in MVP (passwordless email code and phone SMS are out of scope, 2 Nov 2026)
`POST /auth/v1/otp` · **anon**
```json
{ "email": "owner@shop.in", "create_user": true }
{ "phone": "+919824000000", "channel": "sms", "create_user": true }
// 200
{}
```
Errors: 400 invalid phone/email, 429 `over_sms_send_rate_limit` / `over_email_send_rate_limit`, 503 SMS provider error.

### 1.5 Sign in with Google (native ID token)
`POST /auth/v1/token?grant_type=id_token` · **anon**
```json
{ "provider": "google", "id_token": "<Google ID token>", "nonce": "<raw nonce>" }
```
200 session. Errors: 400 `bad_jwt` / nonce mismatch, 401.

### 1.6 Refresh session
`POST /auth/v1/token?grant_type=refresh_token` · **anon** — `{ "refresh_token": "v1.Mr…" }` → 200 new pair (old refresh token revoked; reuse after 10 s → 401 and all sessions revoked).

### 1.7 Forgot password
`POST /auth/v1/recover` · **anon** — `{ "email": "owner@shop.in" }` → 200 `{}` always (no account enumeration). Then 1.2 with `type: recovery`, then 1.9.

### 1.8 Get current user
`GET /auth/v1/user` · **owner** → 200 user object (id, email, phone, identities). Errors: 401.

### 1.9 Update user (new password, add phone/email)
`PUT /auth/v1/user` · **owner** — `{ "password": "New#Pass2" }` or `{ "phone": "+91…" }` (then verify with `type: phone_change`). Errors: 400 weak password, 401, 409 phone/email in use.

### 1.10 Sign out
`POST /auth/v1/logout?scope=local` · **owner** → 204. `scope=global` signs out all devices (Settings → "Sign out everywhere").

## 2. Account & shop — PRD M1, M2, M13, M14

### 2.1 Get profile
`GET /rest/v1/profiles?id=eq.<uid>&select=*` · **owner** → `[{"id":"…","full_name":"Harsh Vaghela","phone":"9824000000","language":"gu",…}]`

### 2.2 Update profile
`PATCH /rest/v1/profiles?id=eq.<uid>` · **owner** — `{ "full_name": "Harsh V", "language": "en" }` → 200 row. Errors: 400 (length/phone check), 401.

### 2.3 Create shop (onboarding)
`POST /rest/v1/rpc/create_shop` · **owner** (only if no shop yet)
```json
{ "p_shop_name": "Vaghela Tailors", "p_owner_name": "Harsh Vaghela", "p_phone": "9824000000", "p_language": "gu", "p_with_sample": false }
// 200
{ "id": "5a0…", "name": "Vaghela Tailors", "next_order_no": 1001, "subscription": { "plan": "trial", "status": "trialing", "trial_ends_at": "2026-12-01T10:00:00Z" } }
```
Creates shop, trial subscription, Shirt + Pant with fields. Errors: 400, 401, 409 `CONFLICT` (shop already exists → returns existing id in `details`).

### 2.4 Get shop + plan
`GET /rest/v1/shops?select=*,subscriptions(*)&deleted_at=is.null` · **owner** → `[ { …shop, "subscriptions": { "plan": "pro_monthly", "status": "active", "current_period_end": "…" } } ]`

### 2.5 Update shop settings
`PATCH /rest/v1/shops?id=eq.<shop_id>` · **owner** — `{ "name", "phone", "gstin", "upi_id", "default_gst_rate", "measurement_unit", "weekly_off_day" }` → 200. Errors: 400 (GSTIN/UPI format), 403 (`owner_id`/`next_order_no` changes rejected by trigger).

### 2.6 Delete account
`POST /functions/v1/delete-account` · **owner**
```json
{ "confirm": "DELETE" }
// 202
{ "status": "scheduled", "purge_at": "2026-11-08T10:00:00Z" }
```
Signs out all sessions, marks shop `deleted_at`, hard-deletes the auth user and all shop rows after 7 days (cancelling = sign in again within 7 days). Errors: 400 (confirm text), 401, 500.

## 3. Sync (generic, all synced tables) — PRD M12

Synced tables: `garment_types, measurement_fields, customers, measurements, measurement_values, measurement_versions, orders, order_items, order_extras, payments` (+ V2 tables). Push order follows FKs (parents first).

### 3.1 Pull changes
`GET /rest/v1/{table}?shop_id=eq.<shop_id>&or=(updated_at.gt.<cursor>,and(updated_at.eq.<cursor>,id.gt.<last_id>))&order=updated_at.asc,id.asc&limit=500` · **owner**
→ 200 array of rows **including** soft-deleted ones (tombstones). Client stores the last `(updated_at, id)` as the cursor per table. Errors: 401 (refresh then retry), 5xx (backoff).

### 3.2 Push changes (upsert batch)
`POST /rest/v1/{table}?on_conflict=id` · **owner** (inserts of `customers`/`orders` need **owner+plan**)
Headers: `Prefer: resolution=merge-duplicates,return=representation`
```json
[ { "id": "9f2…", "shop_id": "5a0…", "name": "Amit Shah", "phone": "9824012345", "book_no": "101", "updated_at": "2026-11-01T09:12:03Z" } ]
```
→ 201 rows with server `updated_at`. Last-write-wins: the trigger rejects an update whose client `updated_at` is older than the stored row (row returned unchanged; client keeps the server version). Errors: 400, 401, 402 `PLAN_REQUIRED`, 409 `CONFLICT` (e.g. `orders(shop_id, order_no)` → client calls 4.4 and re-pushes), 403.

Soft delete = push the row with `deleted_at` set. Hard `DELETE` is never used by the app (no DELETE policy → 403).

## 4. Orders — PRD M7, M8, M10

### 4.1 List orders (server read; app normally reads SQLite)
`GET /rest/v1/orders?select=*,customers(name,phone),order_items(*),payments(amount)&deleted_at=is.null&status=in.(received,ready)&order=due_date.asc&limit=50` · **owner**
Filters supported by the app: `status`, `due_date=lt.<today>` (late), `due_date=eq.<today>`, `is_urgent=eq.true`, `customer_id=eq.`, sort `order_date.desc` / `due_date.asc`.

### 4.2 Get one order
`GET /rest/v1/orders?id=eq.<id>&select=*,customers(*),order_items(*),order_extras(*),payments(*)` with `Accept: application/vnd.pgrst.object+json` → 200 object; 404 if none.

### 4.3 Create order (atomic, online path)
`POST /rest/v1/rpc/create_order` · **owner+plan**
```json
{
  "p_order": { "id": "c1d…", "customer_id": "9f2…", "due_date": "2026-11-08", "is_urgent": false, "notes": "Wedding on 10th", "discount": 50, "gst_rate": 0, "created_via": "app" },
  "p_items": [ { "id": "e01…", "garment_type_id": "aa1…", "qty": 2, "rate": 650, "styles": { "Collar": "Mandarin" } } ],
  "p_extras": [ { "id": "e11…", "label": "Lining", "amount": 150 } ],
  "p_advance": { "id": "p01…", "amount": 1000, "mode": "upi" }
}
// 200
{ "id": "c1d…", "order_no": 1004, "total": 1400, "paid": 1000, "balance": 400 }
```
Checks: customer belongs to shop; every item's cloth has a current measurement for that customer; qty 1–50; rate entered; advance ≤ total. Errors: 400, 401, 402 `PLAN_REQUIRED`, 404 customer/cloth, 422 `BUSINESS_RULE` (`MEASUREMENT_MISSING` with `details.garment_type_id`, `ADVANCE_EXCEEDS_TOTAL`).
Offline path: rows are written locally with a provisional `order_no` and pushed via 3.2.

### 4.4 Claim next order number
`POST /rest/v1/rpc/claim_order_no` · **owner** → `1005`. Used to fix an offline number clash. Errors: 401.

### 4.5 Change status
`POST /rest/v1/rpc/set_order_status` · **owner**
```json
{ "p_order_id": "c1d…", "p_status": "delivered", "p_on": "2026-11-01" }
// 200
{ "id": "c1d…", "status": "delivered", "delivered_on": "2026-11-01", "balance": 0 }
```
Allowed moves: received→ready→delivered and one step back (Undo). Sets `ready_on`/`delivered_on`. Errors: 400 bad status, 404, 422 `INVALID_TRANSITION`, `ORDER_CANCELLED`.

### 4.6 Cancel order
`PATCH /rest/v1/orders?id=eq.<id>` — `{ "cancelled_at": "2026-11-01T10:00:00Z", "cancel_reason": "Customer changed mind" }` · **owner** → 200. Refund = 6.2 with a negative amount. Errors: 400, 404.

### 4.7 Restore a cancelled order
`PATCH /rest/v1/orders?id=eq.<id>` — `{ "cancelled_at": null, "cancel_reason": null }` · **owner** → 200. Errors: 404.

### 4.8 Repeat order
No endpoint: the app pre-fills the new-order flow from an old order and calls 4.3. Orders are **not editable** after creation (PRD M7/M8); items and extras are only written inside 4.3 or by sync push of a newly created order.

## 5. Customers & measurements — PRD M5, M6

### 5.1 Search customers
`GET /rest/v1/customers?shop_id=eq.<id>&deleted_at=is.null&or=(name.ilike.*ami*,phone.like.*ami*,book_no.eq.ami)&order=name.asc&limit=20` · **owner** → 200 array.

### 5.2 Create / update customer
`POST /rest/v1/customers?on_conflict=id` (upsert) · create needs **owner+plan**, update **owner**
```json
{ "id": "9f2…", "shop_id": "5a0…", "name": "Amit Shah", "phone": "9824012345", "book_no": "101", "area": "Navrangpura" }
```
Errors: 400 (name 2–50, phone format), 402, 409.

### 5.3 Next book number
`POST /rest/v1/rpc/next_book_no` · **owner** → `"104"`.

### 5.4 Delete customer (soft)
`PATCH /rest/v1/customers?id=eq.<id>` — `{ "deleted_at": "<now>" }` · **owner**. App blocks if the customer has active orders (client rule; server keeps FK).

### 5.5 Get customer measurements
`GET /rest/v1/measurements?customer_id=eq.<id>&deleted_at=is.null&select=*,measurement_values(field_id,value_in)` · **owner**.

### 5.6 Save measurement (with history)
`POST /rest/v1/rpc/save_measurement` · **owner**
```json
{ "p_id": "m01…", "p_customer_id": "9f2…", "p_garment_type_id": "aa1…", "p_notes": "Loose at chest", "p_values": { "f-length": 29, "f-chest": 40.5 } }
// 200
{ "id": "m01…", "version_saved": true }
```
Copies the old values to `measurement_versions` before overwriting. Errors: 400 (value range), 404, 409. Offline path pushes `measurements`, `measurement_values`, `measurement_versions` via 3.2.

### 5.7 Measurement history
`GET /rest/v1/measurement_versions?measurement_id=eq.<id>&order=created_at.desc&limit=10` · **owner**.

## 6. Payments — PRD M8

### 6.1 Add payment
`POST /rest/v1/payments?on_conflict=id` · **owner** (allowed when plan expired: collecting money stays possible)
```json
{ "id": "p02…", "shop_id": "5a0…", "order_id": "c1d…", "amount": 400, "mode": "cash", "paid_on": "2026-11-01" }
```
Errors: 400 (`amount <> 0`), 404/409 FK. The app blocks amount > balance (client rule, plus check in `create_order`).

### 6.2 Refund
Same as 6.1 with negative `amount` and `note`. 

### 6.3 Remove payment (soft)
`PATCH /rest/v1/payments?id=eq.<id>` — `{ "deleted_at": "<now>" }`.

## 7. Cloth types & fields — PRD M4

`GET /rest/v1/garment_types?deleted_at=is.null&order=sort_order&select=*,measurement_fields(*)` · **owner**
`POST /rest/v1/garment_types?on_conflict=id` — `{ "id", "shop_id", "name": "Kurta", "sort_order": 3, "style_options": {"Neck":["Round","V"]} }` · **owner**. Errors: 400, 409 (duplicate name).
`POST /rest/v1/measurement_fields?on_conflict=id` — `{ "id", "shop_id", "garment_type_id", "name": "Neck", "sort_order": 1 }`.
`PATCH …?id=eq.<id>` — rename, reorder, soft delete (`deleted_at`). App blocks deleting a cloth used by an active order (422 shown client-side).

## 8. Home "Today" — PRD M9
No endpoint. Home is computed from local SQLite (orders, payments) so it works offline.

## 9. Subscription — PRD M14

### 9.1 Restore / check entitlement
Done in the app with the RevenueCat SDK (`Purchases.getCustomerInfo()`); the server source of truth is `subscriptions` (2.4).

### 9.2 RevenueCat webhook
`POST /functions/v1/revenuecat-webhook` · **service** (verified by `Authorization: Bearer <REVENUECAT_WEBHOOK_SECRET>`; JWT check disabled for this function)
```json
{ "event": { "id": "evt_123", "type": "RENEWAL", "app_user_id": "0b6…", "product_id": "truefit_pro_monthly", "expiration_at_ms": 1767225600000 } }
// 200
{ "ok": true }
```
Maps `INITIAL_PURCHASE/RENEWAL/UNCANCELLATION` → `active`, `BILLING_ISSUE` → `grace`, `CANCELLATION` → `cancelled` (still active until period end), `EXPIRATION` → `expired`. Idempotent on `event.id` (`last_event_id`). Errors: 401 bad secret, 400 unknown payload, 404 unknown user (logged, 200 returned so RevenueCat stops retrying).

### `POST /functions/v1/ai-chat` (V2)
```json
// request
{ "messages": [ { "role": "user", "content": "Which orders are late?" } ], "language": "gu", "context": { "today": "2026-11-01" } }
// 200
{ "reply": "2 orders are late: #1001 Amit (2 days), #1006 Neha (1 day).", "cards": [ { "type": "order_list", "order_ids": ["c1d…","c7a…"] } ], "usage": { "input_tokens": 812, "output_tokens": 64 } }
```
